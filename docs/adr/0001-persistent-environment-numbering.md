# 靶场编号持久化，路径仍是唯一身份

为了让用户能用 `pull 1,2,68` 这样的短编号指代靶场，工具维护一份持久化的"靶场路径 → 编号"索引（`~/.local/share/vulhub-cli/index.json`）。编号在 `init` 时按路径字典序一次性分配，此后不随 vulhub 更新改变；`update` 带来的新靶场追加到末尾，消失的靶场其编号作废且不复用。

**替代方案**是每次 `ls` 时按当前目录内容现算行号。它零状态、实现最简单，被否决的原因是**它会安静地出错**：用户昨天看到 68 号是某个靶场，跑完 `update` 后 68 号指向了别的东西，而工具不会提醒他。任何需要"记住几个编号、待会儿再用"的用法（写进脚本、口头传达给同事）在这种方案下都是错的。

**代价**是这个工具从无状态变成了有状态，多出一个需要维护、可能损坏、可能丢失的文件；而索引一旦丢失重建，所有编号都会重新分配。因此配套规定：**靶场路径才是唯一身份，编号只是它的别名**，两者在所有命令中都可使用。编号失效时用户仍能用路径精确表达意图，工具不会因为编号乱了而不可用。
